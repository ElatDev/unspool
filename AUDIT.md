# Safety audit

unspool was extracted from a private packet-inspection tool that ran on my own
machine, next to captures of my own traffic. Before writing any code here, I
audited what could leak. This is the record of that audit.

**Result: a clean repository, no history carried over, and not one byte of any
real capture in this project.**

## What the source project contained

The original tool (`http-viewer`, private) held, next to its source:

| Item | Verdict |
|---|---|
| `captures/capture-*.pcapng` — 134 MB of my own traffic | never copied |
| `captures/sample.pcapng` — "synthetic", but generated with my LAN address and real server IPs | never copied |
| `data/history.json` and friends — recorded sessions, resolved hosts, matched flows | never copied |
| `tools/make_sample_capture.py` — hardcoded my LAN IP, two real service IPs and a real hostname | rewritten from scratch |
| `tests/test_dissect.py` — a real hostname and real IP addresses in fixtures | rewritten from scratch |
| `README.md` — my local filesystem paths, my LAN subnet | not carried over |
| `httpviewer/pcap.py`, `dissect/layers.py`, `dissect/apps.py` — parser code, no addresses | read for reference, rewritten |

## Git history

The source project was **not a git repository** — there was no `.git`
directory and no history to leak. This repository was created fresh with
`git init`, so no capture, path or address has ever been committed, and there
is no deleted-but-recoverable blob to worry about.

Had there been a history containing captures, the plan was the same one the
brief recommends: start a clean repository and copy source files across, never
try to rewrite history.

## What ships instead

Every byte of test data in this repository is generated by
[`tests/synth.py`](tests/synth.py), which builds frames and files from nothing
and uses only addresses reserved for documentation:

- IPv4: `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` (RFC 5737)
- IPv6: `2001:db8::/32` (RFC 3849)
- Names: `example.com`, `example.net`, `example.org` (RFC 2606)
- MAC addresses: locally administered (`02:00:5e:...`), never a real vendor prefix

`examples/demo.pcapng` — the only capture file in the repository — is written
by [`tools/make_demo.py`](tools/make_demo.py) from those builders. Regenerate
it any time with `python tools/make_demo.py`; the output is byte-for-byte
reproducible.

The Wireshark sample captures used to check unspool against `tshark` are
**downloaded, never committed**: `.cache/` is ignored by git. What is committed
is [`compat/manifest.tsv`](compat/manifest.tsv), which records each file's name,
size and SHA-256 so anyone can verify they compared the same bytes.

## Standing rules for this repository

1. No capture from any real network, mine or anyone else's, is ever committed.
2. No address, hostname, interface name or filesystem path from my machine
   appears in code, tests, fixtures or documentation.
3. `.gitignore` refuses `*.pcap` and `*.pcapng` by default; `examples/` is the
   single, explicit exception.
4. The library never writes capture files and never opens a network socket, so
   it cannot create this problem at runtime either.

## Scope, which is also a safety decision

unspool parses capture files. It does **not** capture traffic. The capture half
of the original tool needed `pktmon`, which needs administrator rights and only
exists on Windows. Leaving it out means the project installs anywhere, needs no
privileges and no driver, and cannot produce a file containing anyone's
traffic — including mine. See the README's "Where it stops" section.
